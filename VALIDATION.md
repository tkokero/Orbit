# Orbit 1.0 setup and Roblox validation

- 51 automated Node tests passed, including Roblox URL validation, exact-place routes, public thumbnail matching, store feeds, requirements, download estimates, installer dispatch/cancellation, and existing library behavior.
- 16 production-frontend integration checks passed with an isolated test bridge. Coverage includes first-run wizard opening, progress persistence, Later, completion, restart behavior, reopening from Settings, all 14 themes, decoded installation/deal thumbnails, and Roblox add/edit/remove/launch preference controls.
- Wizard layout checked at 940, 1280, and 1920 pixels without horizontal overflow.
- A live Steam store image was downloaded and decoded through the production cache as a compact JPEG. Game installer and account actions were stubbed in tests; no installation, account connection, or Roblox game join was performed.
- Roblox experience routes follow official game page and client-link formats. The browser route is the default; direct-client support depends on Roblox installation and platform support. The launch test validates dispatch rather than joining an online session.

The setup wizard is part of the actual application. No new standalone demo is built or shipped. Automated UI fixtures are test data only, not the tutorial's content. In normal use the guide reads the user's own Orbit library/settings. Friend information, store prices, and specifications remain subject to their sources and privacy settings.

Roblox experience controls are mounted lazily inside the Roblox details dialog. Interface checks cover the absence of a separate sidebar tab and saved experience CRUD inside the dialog.

Panel dismissal: 22 frontend checks pass, including Ctrl+W, Escape cancellation, outside-click dismissal, protection against inside-to-outside drags, and saved setup progress.

Motion: 28 UI checks pass, including delayed exit cleanup, cancellation when reopening during an exit, and immediate reduced-motion dismissal. Startup shows only after the first paint; discovery remains in its worker.

Startup: 30 UI checks pass. A deliberately delayed initial library response remains behind the Orbit intro; the library is inert until discovery completes. The cover is removed before the setup wizard opens. The finite animation holds a static logo if discovery takes longer.

Scan optimization: 54 automated tests pass. Independent catalog and shortcut reads overlap; unchanged Steam app metadata is shared within the worker. Account enrichment reuses completed discovery. Failed artwork lookups back off for ten minutes, with immediate local recovery and explicit repair bypass. A local comparison retained all 336 records: discovery plus artwork preparation changed from 6006 ms to 4406 ms; network cover/account latency is excluded and timings vary by machine/cache state.

Startup handoff and friends preload: 32 interface checks pass. The intro crossfades into a translated/scaled menu; interaction remains disabled until the finite transition completes. Reduced motion reveals immediately. Friends preloads once, refreshes an existing connection when stale, and reuses the result without duplicate startup requests. Background preload does not open authentication prompts or poll inactive views.

Dynamic platforms and settings: 57 automated tests and 39 frontend checks pass. Saving an experience adds a Roblox platform category with client and experience cards; the last removal restores normal platform grouping. Place IDs use separate merge identities even when titles match. Browser/client routing retains validated URLs. Saved entries do not claim installation, achievements, or individual playtime. Startup-animation and friends preload/refresh preferences are configurable. Shared thumbnail jobs prevent concurrent cache writes.

Minecraft and input recovery: removed the automatic Minecraft download suggestion from Games and migrate only that obsolete built-in record out of saved history. Detected Minecraft Launcher entries are Tools; launcher presence is not ownership evidence. Real detected game packages and manual entries are retained. Startup releases library inert state as soon as data is ready; completion has a deadline and cleans up even if animations stall or throw. Dialog exit and window-close transitions also have bounded fallback completion. Regression checks inject stalled and thrown animations and verify menu clicks still work. 59 automated tests and 42 frontend checks pass.

Installed-app updates: 69 automated tests and 45 frontend checks pass. Tests cover startup/six-hour scheduling, concurrent check deduplication, restart preferences, saved-state handoff before silent install with forced relaunch, errors without quitting, and portable installer guidance. The real electron-updater NSIS download pipeline was exercised against an isolated local feed: a newer payload downloads and validates; a deliberately incorrect SHA-512 is rejected without running an installer. No real account, game, or user app installation was modified by those tests. Production dependency audit reports no vulnerabilities.

Packaging includes a per-user NSIS installer, differential blockmap and latest.yml; generated metadata SHA-512 must match the actual installer before publishing. The installed app uses the fixed public GitHub release URL with prereleases enabled and downgrades disabled. Version 1.0.0-pre.2 introduces the updater; older ZIP copies require one manual installation. A live future-version replacement on an end-user installation is not part of the isolated validation.

Input regression: a real Electron mouse-down, background library snapshot, and mouse-up reproduced a dropped game click before the fix. The same sequence passes with snapshot application deferred until after click dispatch. The frontend suite now passes 46 checks; the Node suite passes 72 tests, including latest-snapshot coalescing, pointer cancellation, focus loss, and unrelated pointer handling. Native light-dismiss is disabled in favor of the existing animated backdrop/Escape dismissal path. This reproduces one cause of lost clicks, but does not establish that it is the only cause of every reported freeze.

The startup handoff now fades only the cover; the menu stays in its final layout and no longer receives an explicit inert lock or restore transform. Real Electron game-card clicks pass after stalled and thrown startup animations without opening another panel first. The control refresh uses shared sizes, rounded corners, theme colors, stationary hover feedback, and visible selection/focus states. Latest checks: 72 Node tests and 48 frontend checks.
